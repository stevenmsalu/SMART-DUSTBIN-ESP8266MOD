## 1. Existing dashboard assessment

### 1.1 Current implementation snapshot

| Attribute | Current state |
|-----------|----------------|
| Location | Single embedded HTML/CSS/JS in `dashboard_page.cpp` |
| Theme | **Dark** (`--bg #0f1419`, dark cards `#1a2332`) |
| Polling | 2.5 s; parallel `GET /api/health` + `GET /api/status` |
| Interaction | **Monitoring only** — no controls (correct for scope) |
| Layout | CSS grid: 1 column mobile; 2 columns ≥ 720 px |
| Sections | Device (5 rows), Approach (1), Lid (3), White LED (1) |

### 1.2 Strengths

- Appropriate data for simplified product (approach, lid, white LED, Wi‑Fi).
- No waste/fill/yellow UI (post–WP-11.3).
- Self-contained (no CDN); suitable for ESP8266 flash.
- Connection banner communicates online/offline.

### 1.3 Weaknesses (examiner / UX)

| Issue | Impact |
|-------|--------|
| Dark “developer console” aesthetic | Conflicts with approved **Fresh Green + Light** direction |
| Title “Smart Dustbin **Monitor**” + subtitle “approach + lid” | Sounds like internal/dev copy |
| Labels **API**, **IP**, **Uptime**, **Servo target**, **Close delay** | Engineering jargon; obscures physical behaviour |
| “Status (lid linked)” | Implementation detail, not user language |
| Approach uses **WARN** styling for “person present” | Amber reads as fault, not normal operation |
| **OPEN** / **CLOSED** raw API strings in lid row | Acceptable technically but cold for demo |
| No single “at a glance” operating summary | Examiner must read four cards |
| Device card mixes connectivity + diagnostics | Dilutes story of automatic bin behaviour |
| Pill text **DETECTED** / **CLEAR** in shout case | Harsh; “clear” ambiguous (sensor clear vs area clear) |

### 1.4 Data available from API (unchanged by this audit)

`/api/status`:

- `approach.detected`
- `lid.state` (`OPEN` | `CLOSED`), `close_delay_pending`, `servo_target_angle_deg`
- `leds.white_on`
- `device.uptime_ms`
- `network.wifi_connected`, `network.ip`

`/api/health`:

- `wifi.connected`, `wifi.ip`
- `features.monitoring_only` (not currently displayed)

All examiner-facing copy can be derived in the **dashboard presentation layer** without API changes.

## 2. Terminology mapping

| Existing term (UI) | Proposed replacement | Reason |
|--------------------|----------------------|--------|
| Smart Dustbin Monitor | **Smart Dustbin** | Drop “monitor”; project name is enough |
| Local read-only dashboard · approach + lid | **Live status from your dustbin** (or **Automatic opening dustbin — live view**) | Plain language; no subsystem names |
| Connecting to device API… | **Connecting to the dustbin…** | “API” is invisible to users |
| Device online · monitoring only | **Connected — view only (no remote control)** | Explains demo constraints clearly |
| API unavailable — showing last data if any | **Connection lost — data may be outdated** | Honest, non-technical |
| **Device** (card title) | **Connection** or fold into footer | “Device” is generic IoT jargon |
| API | **Data link** or remove row | Health check is implicit when page loads |
| Available / Unavailable | **Working** / **Not responding** | Examiner-friendly |
| Wi‑Fi | **Wireless network** (short: **Network**) | Familiar term |
| IP | **Address on network** (short: **Network address**) | Avoid acronym in primary UI; keep value visible for demos |
| Uptime | **Powered on for** | Describes physical meaning |
| Last update | **Last refreshed** | Clearer for polling UI |
| **Approach** (card title) | **Person nearby** | Maps to ultrasonic approach behaviour |
| Detection | **Sensor reading** or merge into one line | Optional; prefer single status line |
| DETECTED (pill) | **Yes — someone is near** | Normal state, not a warning |
| CLEAR (pill) | **No — area clear** | Avoid ambiguous “clear” |
| **Lid** (card title) | **Lid** (keep) | Already physical |
| State | **Position** | Slightly friendlier |
| OPEN / CLOSED | **Open** / **Closed** | Title case, not protocol tokens |
| Servo target | **Motor angle** (secondary) or **Hidden in “Details”** | “Servo” is robotics jargon |
| N° suffix in UI | Keep numeric with **°** only in details | OK for technical appendix |
| Close delay | **Closing soon** | Describes user-visible behaviour |
| Pending | **Yes — lid will close** | |
| Not pending | **No** | |
| **White LED** | **Indicator light** | Examiner sees lamp role |
| Status (lid linked) | **Light on when lid is open** (subtitle) + **On** / **Off** | Removes firmware coupling language |
| ON / OFF | **On** / **Off** | Consistent casing |

**Do not replace** underlying JSON keys (`servo_target_angle_deg`, etc.); only **display strings** in HTML/JS.

## 3. Recommended information hierarchy

### Tier 1 — Immediate (hero / primary card)

**“How is the bin behaving right now?”**

1. **Overall connection** (banner): Connected vs connection problem.
2. **Person nearby:** Yes / No (drives opening).
3. **Lid:** Open / Closed (+ optional “Closing soon” when `close_delay_pending`).
4. **Indicator light:** On / Off (should align with lid open).

*Optional single derived line:* “**Bin is ready**” / “**Bin is open for use**” / “**Bin is closing**” from combining approach + lid + delay (presentation only).

### Tier 2 — Supporting (secondary card or compact rows)

- **Network:** Connected + address (for exam demo on phone/laptop).
- **Last refreshed** + **Powered on for** (proves live firmware).

### Tier 3 — Collapsible “Technical details” (exam appendix)

- Motor angle (`servo_target_angle_deg`).
- Raw millis uptime if needed.
- “View only — no remote control” footnote.

### Remove or demote

| Item | Recommendation |
|------|----------------|
| Separate “API” row | Remove — banner + successful poll implies health |
| Standalone tiny “Approach” card | Merge into Tier 1 hero |
| Servo angle in primary grid | Move to Tier 3 |

## 4. Proposed colour palette (Fresh Green + Light)

Use CSS custom properties. Contrast targets WCAG AA for body text on surfaces.

| Token | Hex | Usage |
|-------|-----|--------|
| `--bg-page` | `#f4f7f5` | Page background (soft green-grey) |
| `--bg-card` | `#ffffff` | Card surface |
| `--bg-card-subtle` | `#eef6f0` | Hero / highlighted strip |
| `--text-primary` | `#1a2e22` | Headings, primary values |
| `--text-secondary` | `#4a5f52` | Labels, supporting text |
| `--text-muted` | `#6b7f73` | Hints, footnotes |
| `--border` | `#d4e4da` | Card borders, dividers |
| `--accent` | `#2d8a4e` | Primary green (headings accent, links) |
| `--accent-strong` | `#1f6b3a` | Hover / emphasis |
| `--accent-soft` | `#e8f5ec` | Success/chip backgrounds |
| `--status-ok` | `#2d8a4e` | Clear area, closed lid idle, connected |
| `--status-active` | `#0d7a6a` | Person nearby / lid open (active, not alarm) |
| `--status-wait` | `#b8860b` | “Closing soon” only (amber, sparingly) |
| `--status-bad` | `#c0392b` | Connection failure |
| `--shadow` | `0 1px 3px rgba(26, 46, 34, 0.08)` | Card elevation (subtle) |

**Avoid** using warning amber for “person detected” — use **active teal-green** or **accent** chip instead.

## 5. Typography and component recommendations

### Typography (system stack — keep zero external fonts)

| Element | Size | Weight | Colour |
|---------|------|--------|--------|
| Page title (`h1`) | 1.35rem | 600 | `--text-primary` |
| Subtitle | 0.9rem | 400 | `--text-secondary` |
| Card title (`h2`) | 0.95rem | 600 | `--accent-strong` |
| Label (`.lab`) | 0.85rem | 400 | `--text-muted` |
| Value (`.val`) | 0.95rem | 600 | `--text-primary` |
| Footnote | 0.8rem | 400 | `--text-muted` |

Line-height: **1.45–1.5**. Max readable line length on mobile: full width with **16px** horizontal padding.

### Components

| Component | Spec |
|-----------|------|
| **Connection banner** | Full width; green left border when OK; light red border when bad; no dark full-bleed |
| **Hero status card** | Single card, `--bg-card-subtle`, 3–4 large status rows with icons optional (Unicode: ○ ●) to save bytes |
| **Status chip** | Rounded pill; border `--border`; background `--accent-soft` for active; not uppercase |
| **Card** | White, `border-radius: 10px`, `padding: 14–16px`, `box-shadow: var(--shadow)` |
| **Grid** | Mobile: 1 col; ≥720px: 2 col; hero spans full width (`grid-column: 1 / -1`) |
| **Rows** | `min-height: 44px` tap-friendly spacing on mobile |

No buttons required (monitoring-only). No images/CDN.

## 6. Responsive layout recommendations

| Breakpoint | Layout |
|------------|--------|
| &lt; 480px | Single column; hero first; connection secondary; technical details accordion at bottom |
| 480–719px | Same; increase padding to 16px |
| ≥ 720px | Hero full width; two-column row: **Connection** \| **Technical details** |

**Issues in current layout**

- Equal-weight cards hide the physical story — **fix with hero-first hierarchy**.
- `.val { text-align: right }` can crunch long IP addresses on narrow screens — allow `word-break: break-all` on address only.
- Pills injecting HTML via `innerHTML` only on approach — unify pattern for lid/LED for consistent styling.

**Do not add** new pages, routes, or controls.

## 7. Proposed final dashboard structure

```text
┌─────────────────────────────────────────────────────────────┐
│  Smart Dustbin                                              │
│  Live status from your dustbin (view only)                    │
├─────────────────────────────────────────────────────────────┤
│  [ Banner: Connected — view only  |  Connection lost ... ]   │
├─────────────────────────────────────────────────────────────┤
│  HOW THE BIN IS BEHAVING                                      │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │ Person nearby .............. No — area clear            │ │
│  │ Lid ........................ Closed                     │ │
│  │ Closing soon ............... No                         │ │
│  │ Indicator light ............. Off                       │ │
│  └─────────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│  [ Connection ]              [ Optional: Technical details ] │
│  Network ........ Connected    Motor angle ... 30°           │
│  Network address  192.168.x.x  Powered on for .. 12m 3s     │
│  Last refreshed .. 22:15:01                                  │
├─────────────────────────────────────────────────────────────┤
│  Footnote: Automatic lid opens when someone approaches.     │
│  Indicator turns on while the lid is open.                    │
└─────────────────────────────────────────────────────────────┘
```

**Display logic (JS, labels only)**

| JSON | User-facing |
|------|-------------|
| `approach.detected === true` | Person nearby: **Yes** |
| `approach.detected === false` | **No — area clear** |
| `lid.state === "OPEN"` | Lid: **Open** |
| `lid.state === "CLOSED"` | Lid: **Closed** |
| `lid.close_delay_pending` | Closing soon: **Yes — lid will close** / **No** |
| `leds.white_on` | Indicator light: **On** / **Off** |

## 9. Implementation sequence

1. **Branch / checkpoint** — confirm clean `main` (Steven policy).
2. **CSS** — Replace `:root` dark tokens with §4 palette; light `body` background.
3. **HTML** — Reorder sections: banner → hero → connection → optional details `<details>` block.
4. **Copy** — Apply terminology table to all visible strings.
5. **JS** — Map API values to friendly strings; fix approach styling (active vs warn); keep `POLL_MS` 2500.
6. **Responsive** — Hero `grid-column: 1 / -1`; test 320px and 768px in browser devtools (host must flash firmware for on-device check).
7. **Compile** — `arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 SmartDustbin`.
8. **Device check** — Browser on LAN: no console errors, banner + hero update every 2.5 s.
9. **Doc** — Short `WP-11.4_COMPLETION_REPORT.md` after implementation authorised.
