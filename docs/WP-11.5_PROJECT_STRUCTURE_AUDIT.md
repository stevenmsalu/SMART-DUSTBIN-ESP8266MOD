## 5. Arduino IDE and Arduino CLI compatibility

### 5.1 Sketch naming and location

| Rule | This project |
|------|----------------|
| Sketch folder name must match primary `.ino` | **Yes** — `SmartDustbin/SmartDustbin.ino` |
| Opening in IDE | Open `SmartDustbin/` (or `SmartDustbin.ino`); not repo root |
| Renaming product sketch | Requires **matching** folder + `.ino` rename together |

### 5.2 How sources are discovered

Per [Arduino sketch specification](https://arduino.github.io/arduino-cli/latest/sketch-specification/) (IDE 1.6.10+ / Arduino CLI):

| Location | Compiled? |
|----------|-----------|
| `.ino` in sketch root | Yes (preprocessed to `.cpp`) |
| `.c` / `.cpp` in **sketch root** | **Yes** — current project layout |
| `.c` / `.cpp` under **`src/`** | **Yes** |
| `.c` / `.cpp` in other subfolders (e.g. `sensors/`, `net/`) **without** `src/` | **No** — silently ignored |
| Headers-only subfolders | Not compiled; visible to `#include` only if on include path |

**ESP8266 core** uses the standard Arduino builder (verified: `arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 SmartDustbin` **succeeds** on WP-11.4 baseline).

### 5.3 Include path implications

Default include paths for a sketch typically include:

- The sketch directory (root of `SmartDustbin/`)
- The `src/` directory (when used)

**Headers placed only in** `SmartDustbin/config/` or `SmartDustbin/include/` are **not** automatically found unless you change includes (e.g. `#include "config/config.h"`) or customise build flags (out of scope for “simple” organisation).

**Recommendation:** Keep `config.h`, `pins.h`, and `wifi_config.h.example` at **sketch root** or move them **together with** `.cpp` partners into **`src/`** using the same flat include style (`#include "config.h"`).

### 5.4 Nested directories under `src/`

Arduino CLI 2.x generally compiles **all** `.cpp` files under `src/` recursively, but **nested include paths** must match folder names (e.g. `#include "sensors/approach_sensor.h"`). That forces **include edits** across the tree.

**Safeguard:** Prefer **flat `src/`** (one level) unless a spike compile proves nested layout with minimal churn.

### 5.5 Can we reorganise without changing the build system?

| Option | Build system change? |
|--------|----------------------|
| Flat sketch root (status quo) | **No** |
| `SmartDustbin.ino` + `src/*.cpp` | **No** — supported natively |
| Domain subfolders outside `src/` | **Yes** — would not compile without PlatformIO/CMake (explicitly out of scope) |
| Rename repo / add `firmware/` wrapper | **No** code change if compile path updated to `firmware/SmartDustbin` |

**Project constraint from README:** *Arduino IDE only (no PlatformIO)* — stay on stock Arduino layout.

## 8. Recommended target directory tree

**Principles:** One sketch folder; minimal nesting; no new build system; preserve module names and APIs.

### 8.1 Target (recommended)

```text
SMART-DUSTBIN-ESP8266MOD/
├── README.md
├── .gitignore
├── docs/                              # unchanged role
├── archive/                           # OPTIONAL: proposal .7z + docx (repo hygiene)
│   └── …
└── SmartDustbin/                      # sketch name unchanged
    ├── SmartDustbin.ino               # setup(), loop(), timing helpers
    ├── config.h                       # global firmware constants (stay at root)
    ├── pins.h
    ├── wifi_config.h.example          # + local wifi_config.h (gitignored)
    └── src/                           # all .cpp and module headers
        ├── application_status.{h,cpp}
        ├── approach_sensor.{h,cpp}
        ├── dashboard_page.{h,cpp}
        ├── gpio_init.{h,cpp}
        ├── hcsr04_common.{h,cpp}
        ├── http_api.{h,cpp}
        ├── lid_control.{h,cpp}
        ├── white_indicator.{h,cpp}
        └── wifi_manager.{h,cpp}
```

**Why not deeper nesting** (e.g. `src/sensors/`, `src/net/`)? Possible with Arduino CLI 2.x, but requires **systematic include path updates** and higher migration risk for a **small** file count (~18 units). Revisit only if the codebase grows substantially.

### 8.2 Alternative A — status quo (valid)

Keep the current flat `SmartDustbin/` layout. **Lowest risk**; address only repo-root `archive/` and documentation drift.

### 8.3 Alternative B — rename sketch (not recommended without product decision)

Renaming to e.g. `smart_dustbin/` would touch IDE habits, README, and all contributor docs. **Defer** unless branding requires it.

## 10. Migration risks and safeguards

| Risk | Mitigation |
|------|------------|
| Sources not compiled after move to wrong folder | Only use sketch **root** or **`src/`**; never `SmartDustbin/lib/foo.cpp` without build change |
| Includes break after nested subdirs | Prefer **flat `src/`**; full `arduino-cli compile` after first file move |
| `wifi_config.h` not found | Keep example + real file paths documented; compile on machine **with** local `wifi_config.h` |
| Git history loss | Use `git mv` for each file |
| IDE stale index | Close/reopen sketch folder after move |
| Concurrent WP work | Migrate from **clean** baseline; avoid mixing with uncommitted functional WP |
| Dashboard/HTML regression | No content change in migration; compile + HTTP smoke test only |
| Duplicate `main` / missing symbols | Do **not** leave duplicate `.cpp` in root and `src/` |

**Rollback:** Single revert commit if migration is one atomic PR.
