## Addendum — HTTP response transport correction

**Date:** 2026-11-19  
**Authorisation:** Approved (post-incident)  
**Incident:** `net::ERR_INVALID_CHUNKED_ENCODING` on `/api/status`, `/api/health`

### Root cause

Handlers used `setContentLength(CONTENT_LENGTH_UNKNOWN)` (→ `Transfer-Encoding: chunked`) then wrote JSON with **`s_server.client().print()`**, bypassing `ESP8266WebServer::sendContent()` chunk framing. Browsers received headers claiming chunked encoding with a body that was not valid chunked data.

This pattern predated the WP-11.3 JSON schema change; dashboard testing after simplification exposed the defect.

### Corrective implementation

**File changed:** `SmartDustbin/http_api.cpp` only.

| Before | After |
|--------|--------|
| `CONTENT_LENGTH_UNKNOWN` + empty `send()` + `client().print()` | Build full JSON in `String` (`buildStatusJson`, `buildHealthJson`) |
| Stream to `Print&` | `s_server.send(200, F("application/json"), json)` |

WP-11.3 JSON field names and structure **unchanged**. No `s_server.client()` body writes in API handlers. No `CONTENT_LENGTH_UNKNOWN` on these routes.
