## 2. Implemented design and terminology

### Header

- **Title:** Smart Dustbin  
- **Subtitle:** Live status from your dustbin  

### Connection banner

- Success: **Connected — view only**  
- Failure: **Connection lost — data may be outdated**  
- No user-visible “API” label.

### Hero — How the bin is behaving

| Label | Display values |
|-------|----------------|
| Something nearby | **Something detected** / **Nothing detected** (active/ok chips) |
| Lid position | **Open** / **Closed** (from `lid.state`) |
| Closing soon | **Yes — lid will close** / **No** |
| Indicator light | **On** / **Off** (from `leds.white_on`) |

Footnote: *Indicator turns on while the lid is open.*

**Sensor accuracy:** No “person” wording. Technical footnote states ultrasonic measures distance only.

### Secondary — Network card

- Connection (Wi‑Fi connected / disconnected)  
- Network address (`word-break: break-all` on narrow screens)  
- Last refreshed (local time)

### Technical details (`<details>`)

- Motor angle (`servo_target_angle_deg` + °)  
- Powered on for (formatted uptime)  
- Footnote: view-only + sensor limitation

## 4. Layout and responsive changes

| Viewport | Behaviour |
|----------|-----------|
| Mobile | Single column; hero first (`grid-column: 1 / -1`); 16 px padding; min row height 44 px |
| ≥ 720 px | Two columns; hero still full width; network + technical details share row |
| Address | `.val.addr` with `word-break: break-all` — avoids horizontal scroll |

**Removed:** Dark theme, separate Device/API/Approach/LED cards, obsolete jargon in primary UI.

**Preserved:** `POLL_MS = 2500`, parallel `fetch('/api/health')` + `fetch('/api/status')`, stale flag on error, monitoring-only (no controls).
