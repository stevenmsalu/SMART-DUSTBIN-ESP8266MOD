## 1. Implementation summary

Replaced fill-based `led_status` with **`white_indicator`**: a single white LED on **D0 / GPIO16** driven by **`lidControlGetLidState()`**.

| Lid state | White LED |
|-----------|-----------|
| `Closed` | OFF (LOW) |
| `Open` (includes close-delay countdown) | ON (HIGH) |

Yellow LED (**GPIO0 / D3**) is no longer configured or driven. **`CONFIG_WARN_*`** fill thresholds removed from `config.h`.

**Loop order:** `lidControlUpdate()` → **`whiteIndicatorUpdate()`** → approach sampling → Wi-Fi/HTTP.

**HTTP/dashboard:** `http_api.cpp` and `dashboard_page.cpp` **unchanged**. `ApplicationStatusSnapshot` still exposes legacy `leds.indicator` / `yellow_on` via `application_status` mapping (`yellow_on` always `false`; `indicator` = `NORMAL` when white on, else `UNKNOWN`) until WP-11.3.

## 6. Implementation details

```cpp
// white_indicator.cpp — core logic
const bool shouldOn = (lidControlGetLidState() == LidPositionState::Open);
```

`LidPositionState::Open` is held during **close delay** (`lid_control.cpp` unchanged), so the white LED stays **ON** through countdown and re-approach cancel scenarios.

Boot: `whiteIndicatorBegin()` sets OUTPUT and **LOW** before any lid motion.

Serial transitions: `[white] ON (lid open)` / `OFF (lid closed)` on change only.
